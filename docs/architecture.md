# 新工程技术架构

## 选择与边界
新建 Godot 4 单机工程；精确稳定版和匹配导出模板由 WORLD 开工核对官方发布后写 project.json，当前不假称锁定。只用原生场景、TileMapLayer、CharacterBody2D、信号和有限服务；不搬入 Web 引擎、Convex、旧运行时或先堆通用 Manager。
参考依据见 [references](references.md)：可编辑图块和小场景负责表现；离散命令、事实与慢操作分离。物理移动本地逐帧响应，不套服务端批量 tick 的延迟模型。

## 目录与所有权
| 目录 | 职责 | 不得拥有 |
| --- | --- | --- |
| game/app | 唯一启动、加载/退出、注入和UI生命周期 | 所有系统私有状态的副本 |
| game/world | 区域场景、共享TileSet、对象门锚、碰撞导航 | 库存、时间或任务奖励 |
| game/actors | 玩家/狗/居民运动、表现适配 | 可直接发奖的模型决策 |
| game/systems | 农耕、库存/经济、居民、任务领域 | UI节点/网络等待 |
| game/persistence | 新档、快照校验、原子写入、恢复 | 从旧目录猜迁移 |
| game/dialogue | 条件对白、可选Provider、上下文 | World写权限或私密Key日志 |
| game/ui | 展示投影、图标/焦点、提交意图 | 可写背包/任务的第二副本 |
| game/content | 版本化物品、作物、价格、居民和任务表 | 动态玩家存档 |
| game/assets | 已登记运行图集、图标、字体与许可 | 原始下载任务缓存 |
| game/tests | 新领域、场景、视觉/导出测试 | 历史测试数量背书 |
| art | 生产清单、风格、任务请求与脱敏收据 | 发布期网络依赖 |

目录占位不是实现。模块按当前能力增加，不提前创建一百个空服务。运行场景以组合为主，不继承多阶段候选链。

## 状态与命令
一个 Session 持有 session_id/generation；每个领域持有唯一业务状态。公共离散命令校验 actor/目标/版本/前置条件后，构建变更集，再在主线程一次提交，最后投影成功事实与UI。
交易、赠礼、交付的多领域修改必须先全验证后一起应用，不能先扣钱再等待异步奖励；提交阶段不 await。幂等回执保存规范请求摘要；同ID不同请求拒绝。瞬态失败重试规则见 [数据合同](data_contracts.md)。
物理移动/鼠标悬停不生成每帧持久命令。UI读取必要投影，变化信号增量更新；不得每帧深拷贝整个日志。

## 时间、转场、保存
Clock 是唯一 game_minute；暂停是持有者token集合，关闭最上层界面释放自己的token，不清掉别人的暂停。日结按 last_settled_day 去重。
转场先准备目标场景与双方落点，再发布玩家/狗新空间；失败或取消双方留原处。generation使迟到加载、动画或AI回包失效；导航数据与布局同源且防斜角切墙。
保存格式全新，只访问 user://qingfeng/；写临时文件、完整校验、保留有效备份，再采用平台验证过的原子替换。恢复先完整解析校验到临时状态，再一次发布；坏档不能半恢复，写盘失败不能丢上一个好档。

## 两个AI边界
PixelLab：仅制作期，素材经下载、校验、版本化后成为普通离线资源；发布包不带token或生成依赖。
居民AI：只做可选表达。请求绑定会话/居民/context_version，超时与失效丢弃，关闭后无新请求；没有Key使用条件对白。模型不执行脚本、不调用奖励、不改变价格/坐标。私人记忆只取有来源的事件，摘要与事实分开，初版不强制向量库。

## 依赖选择
满足需求先用原生能力/已获许可的小组件。新增依赖先记录来源/版本/许可证/替代方式/维护成本；不因为工具宣传“几分钟游戏”就跳过资产与玩法验证。实现后用 [验收](acceptance.md) 证明，不按文件数判断完成。
