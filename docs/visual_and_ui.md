# 视觉、地图与 UI

## 直接对照与标尺
以 [Stardew 官方画面](https://www.stardewvalley.net/press/) 为相机呈现、角色占屏比例、地面/立面关系的直接参考；不打包原游戏图集。固定俯视正交坐标 X 右 Y 下，不采用菱形等距，不杜撰一个 3D 相机俯角作为“完全一致”证据。
以 16×16 原生地形格开始制作。可见格数、角色内容高度、门宽、镜头范围要从同尺寸参考/实现截图测量并记录；角色生成画布不等于角色实际像素高度。PixelLab 的 view 是生成提示，不是 Godot Camera2D 角度。low top-down 仅是待对照的初始候选，所有工具显式传 view，不混用默认值。
展示采用最近邻和整数像素倍率策略，物理位置保留精度；相机/缩放策略在 1280×720、1920×1080 及非整数窗口验证。具体世界视口尺寸由样板锁定，不能为了适应错误素材随意缩放单个物件。

## Phase0 原创菜园首屏（可运行候选，非已验收最终美术）
首批真实像素PNG与地图资源在 `game/assets/phase0/`：16×16地形图集、192×152农舍、80×96橡树、24×32主角四向 idle/walk 帧。640×360 农庄画面改由原生 `TileMapLayer` (`TerrainGround`、`GroundDetails`、按PlotState更新的`PlotStates`) 和可复用 `Sprite2D` 呈现；六块田地Marker、房门/村庄路口、树根/房屋/河道碰撞与保存坐标均不改动。全区域玩家使用同一套四向贴图，现有居民及其他区域地形仍可能为诊断美术。地图和人物资源在 `art/manifest.json` 记录 sha256，`review_status=proposed`，没有用户原设计图同屏对照、PixelLab验收或Godot原生实机截图，不能称为最终素材。原始制作说明见 `art/PHASE0_SOURCE.md`。
正式设计验收仍需 N01–N03 用户视觉审查及 N05 的原生走路/碰撞/绘制回归；当前`GameClock`、田地、门和背包功能不依赖 PixelLab 在线接口。

## 地图唯一来源
共享外部 TileSet + 各区域一份可编辑场景。地形铺格，房屋/树/桥/门是可复用场景组件，田地和作物分层。移动物件只改源布局；运行不得重建一张不同地图覆盖编辑结果。
碰撞对应脚下占地，不按整张透明贴图矩形封路。可走桥面和阻挡栏杆分开；屋檐/树冠可遮挡，树根/墙阻挡。用同一布局导出导航阻挡，不手写另一份墙坐标。AStar 路径只规划，实际位移仍碰撞；斜角不得穿墙。
人物和应按根锚排序的对象位于可比较的同层 Y-sort 群组；不要用全局极大 z 把全部屋顶永远盖在所有角色上。只为确有跨层语义的桥面/前栏声明固定分层。先验证家门—田边—树前后—桥的真实路线，再扩区。
保留物体本身必要侧面、接触阴影与统一受光；“像素”不等于纯俯拍扁平贴纸。不要用加饱和、全屏滤镜代替体块。

## 动作
玩家/狗四向 idle/walk 先通过；只使用实际位移驱动行走，不让正在移动的角色播放脚不动的原地转向。停止、反向、撞墙、失焦、进菜单要能交还表现控制权。
农事先验证向下挥锄一条动作，准备→接触→收势→idle；从元数据 contact 触发一次事务。再扩四向和其他动作。帧数以实际导出及自然度为准，不写死 execute=第1帧，不复制同帧/旋转整个人物冒充过渡。
狗走路必须有对应四向姿势，不能用两张正面图片宣称完整跟随。脚锚、画布、武器/工具接触位置都登记。

## UI 页面规范
按钮尽量同套图标：背包、箱子、交易、地图、任务、设置、保存、返回、狗等待/召回。主菜单和破坏性确认允许必要文字，物品名/数量/价格/任务内容/错误信息不能删除。
图标按钮必须有 tooltip、键盘焦点、可访问名称、禁用原因；选中不只靠颜色；Esc 关闭最上层，关闭后焦点返回触发控件。快捷键与鼠标操作消费同一命令。文字不能烘焙进按钮图片。
新字体优先核验 Noto Sans CJK SC / 思源黑体的 OFL 文件，随游戏包发布；不使用 WenKai 类书法体，不依赖开发机系统中文字体。PixelLab 不制作字体。
主题 token 角色：body、caption、heading、quantity、tooltip、error。字号/行高在实际窗口选定，项目 Theme 为一处来源；页面局部覆盖必须说明。标题、背包、交易、对话和设置都检查中英文、数字、标点、长物品名。
当前 HUD/快捷栏正式骨架直接消费 GameplaySession projection：顶部半透明状态面板分开显示区域/日时/金币/动作提示；底部12格快捷栏居中并使用 Theme slot token。第1–10格标记真实数字快捷键1–0，第11/12格明确为点击选择，不伪造键位；选中态同时使用文字括号、pressed状态和边框/底色，不能只靠颜色。当前仍使用工程文字/线条图标，最终物品图标与随包CJK字体未验收。 背包页复用同一 slot token 与真实12格 Inventory projection：4×3槽位网格保持快捷栏顺序，当前选中槽默认获得焦点，详情区只显示 content_version 已提供的物品名、数量、买/卖价格与真实快捷键语义；UI 不另造用途/价格字典，也不持有可写背包副本。 家庭箱子页沿用同一 slot token：左侧12格随身背包、右侧24格木箱同屏展示，容量占用数从真实 slots 计算；非空槽点击仍发送 storage.transfer 整组移动 intent，空槽只显示容量位置且不可点击，不再需要滚动寻找另一容器。 杂货铺交易页同样改成购买/出售双区：顶部只显示权威日时、营业状态/时段与金币；购买只列 buy_price>0 商品，出售只列背包当前持有且 sell_price>0 物品，打烊时交易按钮禁用并保留文字原因。UI 仍只发送 economy.buy/economy.sell intent。 暂停页改成游戏内状态摘要+四个固定操作：继续、保存、设置、保存并返回；摘要只读当前区域、日时、金币和can_save，默认焦点回到继续。保存按钮禁用与否仍由会话是否可保存决定，暂停/输入token和Esc最上层规则不因视觉重排改变。 设置页拆成声音/显示两区：master_volume slider 同步显示百分比，全屏/VSync 保留文字、tooltip 与无障碍名；预览仍只创建临时 draft。显示确认页单独强调10秒倒计时和失焦/Esc自动恢复，只有确认按钮才持久化设置。 标题页只保留“晴风谷 / 一段新的乡居生活”和继续、新建、存档、设置、退出五个真实入口，不再向玩家展示开发版/工程状态文案；无最近存档时继续禁用，有存档时继续获得默认焦点。最终标题背景与Logo素材后续可替换表现，但不改变入口结构。 新档页只保留首版真实身份输入：玩家名必填、狗名可留空，两个输入都沿用16字上限和现有校验；创建说明明确会生成新的独立存档并从农庄第一天开始，已有存档不会被覆盖，不再展示伙伴系统尚未接入等工程提示。 读档页将 `store.list_saves()` 的每一项直接呈现为存档卡：有效档显示玩家名、狗名（若有）、保存区域、saved_at_utc 与 content_version；无效档保留错误码且读取按钮禁用。UI 不根据 `game_minute` 自行推导天数/时间，避免复制 GameClock 规则。 导入确认页只读冻结的 preview envelope，显示同样的身份/区域/保存时间/content_version，并明确确认后生成新的本机存档副本和本地会话身份；原文件与现有本机存档都不被修改。 加载中页只显示真实可描述阶段“加载场景并校验安全落点”，不伪造百分比；Esc/取消返回标题的动作保持原入口逻辑。 首个正式对白页使用覆盖在世界底部的对话框，而不是全屏菜单：保留世界画面、显示居民名/authored正文/结束动作，打开时由 `dialogue` input/pause owner 冻结玩家输入和唯一 GameClock；UI 不直接写事实、关系或居民状态。 邻居回访对话底部新增可禁用的赠礼按钮：展示当前选中可赠物（萝卜/野菜）、关系增益与每日限额，首次相识、工具/空槽或今日已赠礼会明确提示不能送。点击只发 `resident.gift` intent，领域结算成功后仍停留在对话框内展示结果；同一对话框现已支持杂货铺店主，柜台交易与店主 E 交谈是独立可达目标；最终图标素材未验收。

## 验收
同镜头给参考与实现，记录 commit、源图 hash、视口、倍率、内容高度与未验项。图集通过只证明可接入；视觉 accepted 必须有人或指定审查者签名及证据。路径录像必须实际走路，传送站位只能证明局部遮挡。
素材生产细节见 [PixelLab](pixellab_pipeline.md)，自动/原生测试见 [验收](acceptance.md)。
